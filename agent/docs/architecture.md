# ULT Polsri AI Service Agent: Architecture & Implementation Guide

## 1. System Overview

The **ULT Polsri AI Service Agent** is an automated, grounded assistant built for the **Unit Layanan Terpadu (ULT) of Politeknik Negeri Sriwijaya (Polsri)**. Its mission is to provide accurate, verified information regarding university services and administrative procedures (academic letters, leave of absence, legalization, campus facilities, and complaints) while strictly adhering to a **zero-hallucination / honest fallback** policy.

The agent is implemented using **LangGraph (Python)** and served via **LangGraph Server** (`langgraph.json`), allowing instant interoperability with **LangChain Agent Chat UI** and future custom web clients (e.g. React/Next.js).

## 2. Graph Pipeline & State Design

The core execution engine is a deterministic `StateGraph` designed to guarantee safety, relevancy, and groundedness before presenting any answer to the user.

```
       [ START ]
           │
           ▼
    ┌──────────────┐
    │ input_guard  │──(injection detected)──► [ END ]
    └──────────────┘
           │ (valid query)
           ▼
    ┌──────────────┐
    │ query_refine │──(complaint / wants officer)──► ┌──────────┐
    └──────────────┘                                 │ escalate │──► [ END ]
           │ (general procedure query)               └──────────┘       ▲
           ▼                                                            │
    ┌──────────────┐                                                    │
    │   retrieve   │                                                    │
    └──────────────┘                                                    │
           │                                                            │
           ▼                                                            │
    ┌──────────────┐                                                    │
    │grade_context │──(insufficient context)──► ┌──────────┐            │
    └──────────────┘                            │ fallback │────────────┘
           │ (context sufficient)               └──────────┘  (repeated fallback >= 2)
           ▼                                         │
    ┌──────────────┐                                 ▼
    │generate_ans  │                              [ END ]
    └──────────────┘
           │
           ▼
    ┌──────────────┐
    │ output_guard │──(verified answer)──► [ END ]
    └──────────────┘
```

### 2.1 State Schema (`AgentState`)

Defined in `src/agent/state.py`:

| Field | Type | Description |
|---|---|---|
| `messages` | `Annotated[List[AnyMessage], add_messages]` | Conversation history containing user and AI turns |
| `category` | `Optional[str]` | Detected service category (`academic`, `student_affairs`, `general_admin`, `unit_info`, `complaints`) |
| `rewritten_query` | `str` | Standalone query with pronouns and conversational references resolved |
| `retrieved_documents` | `List[ULTDocument]` | Chunks retrieved from NeonDB with similarity scores and metadata |
| `context_sufficient` | `bool` | Flag indicating whether similarity scores pass the relevance threshold (0.65) |
| `generated_answer` | `Optional[str]` | The synthesized response generated by Gemini 3.8 Flash |
| `citations` | `List[str]` | Distinct official document titles cited in the response |
| `guard_warnings` | `List[str]` | Security notices (e.g., PII redaction alerts) |
| `fallback_count` | `int` | Counter tracking consecutive unresolved questions |
| `needs_escalation` | `bool` | Trigger for human officer contact details |

### 2.2 Node Breakdown

1. **`input_guard`** (`src/agent/nodes/guards.py`)
   - **Privacy Guard**: Regex matching scans for Indonesian student IDs (NIM: 8-12 digits), National IDs (NIK: 16 digits), and phone numbers. Redacts them inline with `[DIRAHASIAKAN]` placeholders and adds a friendly warning advising users not to share sensitive data.
   - **Adversarial Guard**: Checks for system prompt extraction attempts, jailbreaks, and instructions attempting to override agent persona. Halts execution with a polite refusal if detected.

2. **`query_refine`** (`src/agent/nodes/query.py`)
   - Resolves context-dependent inquiries (e.g. "berapa biayanya?" → "Biaya legalisir ijazah di ULT Polsri") using `gemini-3.8-flash`.
   - Categorizes inquiries into the 5 official ULT service domains.
   - Detects explicit requests for human officers or complaint submissions, setting `needs_escalation = True`.

3. **`retrieve`** (`src/agent/nodes/retrieval.py`)
   - Queries NeonDB `ult_knowledge_base` using cosine distance with `gemini-embedding-2`.
   - Applies metadata filtering by `category` and returns top-4 passages.

4. **`grade_context`** (`src/agent/nodes/grading.py`)
   - Compares the top retrieved chunk score against `SIMILARITY_SCORE_THRESHOLD` (default: 0.65).
   - If confidence is high, routes to generation; if evidence is weak or absent, routes to fallback.

5. **`generate_answer`** (`src/agent/nodes/generation.py`)
   - Formulates responses in Indonesian using formal-friendly tone ("Anda").
   - Follows standard administrative formatting: Requirements, Steps, Responsible Unit, Official Form Link, and Citations.
   - Strictly refuses to invent dates, hours, or URLs not present in the retrieved passages.

6. **`output_guard`** (`src/agent/nodes/guards.py`)
   - Verifies the answer text for unauthorized commitments (e.g., claiming to have approved or issued documents). If found, overrides the answer with an informative procedural explanation.

7. **`fallback` & `escalate`** (`src/agent/nodes/fallback_escalate.py`)
   - `fallback`: Provides honest missing-information notices and increments the fallback counter.
   - `escalate`: Automatically triggers when `fallback_count >= 2`, when a complaint is identified, or when requested by the user, providing official operating hours, office location, WhatsApp, and helpdesk URLs.

## 3. Vector Database Architecture (NeonDB + pgvector)

The agent connects to a remote NeonDB PostgreSQL instance configured with the `pgvector` extension.

### Schema Design (`ult_knowledge_base`)

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS ult_knowledge_base (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    entry_id VARCHAR(64),                      -- e.g. FAQ-01-001
    category VARCHAR(64) NOT NULL,             -- academic, student_affairs, general_admin, unit_info, complaints
    title VARCHAR(255) NOT NULL,               -- Service procedure title
    content TEXT NOT NULL,                     -- Text chunk
    embedding VECTOR(768),                     -- 768 dimensions for Gemini Embedding 2
    source_title VARCHAR(255) NOT NULL,        -- Official document name
    source_ref VARCHAR(255),                   -- SK document number
    form_url VARCHAR(500),                     -- Downloadable form URL
    responsible_unit VARCHAR(128),             -- Assigned unit (e.g., Bagian Akademik)
    verified_at DATE DEFAULT CURRENT_DATE,     -- Validation timestamp
    valid_until DATE,
    version INT DEFAULT 1,
    status VARCHAR(32) DEFAULT 'published'     -- draft, in_review, published, archived
);

CREATE INDEX IF NOT EXISTS ult_kb_embedding_hnsw_idx 
ON ult_knowledge_base USING hnsw (embedding vector_cosine_ops);
```

## 4. LangGraph Server & Client Interoperability

The agent is exposed via `langgraph.json`:

```json
{
  "dependencies": ["."],
  "graphs": {
    "ult_agent": "./src/agent/graph.py:graph"
  },
  "env": "./.env"
}
```

* **Development Command**: `langgraph dev --port 2024`
* **Protocol**: Exposes standard LangGraph Server HTTP & Server-Sent Events (SSE) endpoints (`/threads`, `/runs/stream`).
* **LangChain Agent Chat UI**: Point the Next.js UI (`http://localhost:3000`) to `http://localhost:2024` with graph ID `ult_agent`.
* **Future React Client**: Can communicate directly via `@langchain/langgraph-sdk` or standard streaming fetch requests without modifying backend code.
